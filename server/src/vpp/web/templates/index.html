How the buzz works

  1. Pay straight to the recipient

    Checkout runs on Stripe, and the money goes into the recipient's own account. We never touch it.

  2. Everyone sees the same ledger

    Each payment is signed and added to a public ledger. Outside witnesses check that nobody rewrites it, and you get a receipt to keep.

  3. The recipient signs for it

    They tap a passkey tied to their own website. Payments they've signed for show as confirmed. The rest show as recorded.

Try to cheat the ledger

Don't trust the bee

The verifier is a separate program that shares no code with this site. It redoes every check itself, using copies kept by people other than us.

It's open source: read the code on GitHub, or install it from PyPI.

pip install donationbee-verify
vpp-verify --url {{ base }} --pin-genesis <hash> \
  --witness <witness vkey> --min-witnesses 1 \
  --anchors-repo {{ anchors_url() or '<anchors git url>' }} --check-ots --check-domains

What even a good bee can't prove

  • A payment the recipient hasn't confirmed is our word that Stripe reported it.
  • A payer and recipient who know each other look like strangers.
  • The operator and a recipient working together could invent one.
  • Money sent back outside Stripe is invisible to any ledger.
